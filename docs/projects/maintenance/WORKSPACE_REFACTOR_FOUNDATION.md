# Workspace Refactor Foundation

## Purpose

Retain the core critique of workspace-refactor pressure so future cleanup work
can start from an already-reasoned baseline.

## Current judgment

The legacy workspace was stronger on durability than on discoverability.

## Durable strengths

- clear separation between active work, archives, runbooks, and daily memory
- strong proof-preservation discipline
- explicit maintenance process instead of ad hoc cleanup

## Durable frictions

- too many parallel restart and handoff summaries
- repeated canonical facts across multiple control docs
- uneven project-level indexing and discovery cost
- archive families that remain durable but expensive to scan quickly

## Guardrails for future broad refactor work

- do not flatten the workspace just to make it look tidy
- do not merge archives back into active project trees
- do not create new parallel handoff layers
- preserve durable proof and historical patch lineage
- prefer better indexing and lifecycle clarity over broad folder churn

## Current use

Treat this document as a future cleanup foundation, not as a mandate to broaden
the current restoration pass.
