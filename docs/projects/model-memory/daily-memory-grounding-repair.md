# Daily Memory Grounding Repair

## Problem

The canonical workspace daily note `memory/2026-04-18.md` was missing even
though the retained `session-memory` hook had already been restored and was
expected to keep same-day grounding intact.

That was an actual continuity gap, not a cosmetic one:

- operator review context for `2026-04-18` explicitly recorded the exact daily
  note as missing
- same-day grounding fell back to archived evidence instead of the canonical
  daily note surface
- the repo had started depending on the hook again as a continuity producer, so
  the hook contract needed to match that reality exactly

## Exact root cause

The bug was in the retained `session-memory` hook implementation.

Affected runtime surface:

- [handler.ts](/root/services/openclaw-roles/live/src/hooks/bundled/session-memory/handler.ts)

What the hook did before the repair:

- wrote a per-session leaf note under `memory/YYYY-MM-DD-<slug>.md`
- did **not** append or create the canonical day file
  `memory/YYYY-MM-DD.md`

Why that caused the gap:

- slugged leaf notes and the canonical daily note are not interchangeable
- current operator review and continuity expectations treat
  `memory/YYYY-MM-DD.md` as the primary same-day grounding file when it exists
- the hook therefore looked "restored" while still failing the actual
  continuity contract

## Failure classification

- classification: `generation_path_incomplete`
- subtype: `canonical_daily_note_never_written`
- not the cause:
  - workspace permission failure
  - date-resolution bug
  - container-only path mismatch
  - ownership overwrite bug

## Repair implemented

Code changes:

- [handler.ts](/root/services/openclaw-roles/live/src/hooks/bundled/session-memory/handler.ts)
- [handler.test.ts](/root/services/openclaw-roles/live/src/hooks/bundled/session-memory/handler.test.ts)

Behavior after the repair:

1. `/new` and `/reset` still write the slugged session leaf note.
2. The same event now also appends a structured entry to
   `memory/YYYY-MM-DD.md`.
3. The canonical daily file is created when absent.
4. Existing operator-authored daily content is preserved and extended.
5. Duplicate append is prevented by session-id matching.

## Canonical daily note contract after repair

- canonical file: `memory/YYYY-MM-DD.md`
- producer: retained `session-memory` hook on session boundary commands
  `/new` and `/reset`
- auxiliary file: `memory/YYYY-MM-DD-<slug>.md`
- canonical role of auxiliary file:
  - per-session leaf artifact
  - provenance pointer for deeper review
- canonical role of the daily file:
  - same-day continuity grounding surface
  - operator-review and memory-grounding primary markdown note when present

## Ownership model

Auto-generated by the hook:

- timestamped entry block
- session key
- session id
- source
- pointer to the slugged leaf note
- bounded conversation summary when available

Human-owned and preserved:

- existing note content in `memory/YYYY-MM-DD.md`
- operator annotations already present in the file

Overwrite rule:

- append only
- never rewrite the full daily note
- never remove existing human-authored content

## 2026-04-28 continuity reliability repair

The later live operator digests showed that canonical daily notes were still
not appearing reliably:

- `memory/2026-04-23.md` was missing
- `memory/2026-04-26.md` was missing
- `memory/2026-04-27.md` was missing
- `memory/2026-04-28.md` was missing at repair start

The retained hook still owns `/new` and `/reset` capture, but hook firing alone
is not a sufficient reliability guarantee for the default daily workflow.

Additional repair:

- add bounded hook telemetry under
  `archives/session_memory_hook/YYYY-MM-DD.md`
- add repo-owned finalizer
  `ops/reviews/daily_memory_continuity_finalizer.sh`
- schedule the finalizer near end of day from host cron
- create `memory/YYYY-MM-DD.md` only when exact same-day durable evidence
  exists
- skip and report when only stale fallback evidence exists

Backfill rule for this repair:

- allowed: same-day session leaf notes, same-day daily operator review
  artifacts, same-day daily memory evidence artifacts, same-day DB-backed
  evidence artifacts, and same-day bounded cron/native summaries
- blocked: older DB artifacts, stale weekly summaries, inferred memory, raw
  prompts, full transcripts, raw tool logs, secrets, and private phrases

Authority rule:

- canonical daily notes are continuity and ingestion surfaces only
- they are not semantic truth authority and must not override model-memory
  lifecycle, conflict, supersession, or provenance state
