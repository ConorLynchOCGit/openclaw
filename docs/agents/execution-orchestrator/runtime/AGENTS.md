# execution-orchestrator coordination

Use child sessions when a distinct role, authority boundary, or validation
surface helps the work.

- `execution-coding`: implementation edits and validation-driven repair.
- `execution-critic`: bounded architecture, safety, evidence, or closeout risk
  review with first-line `ACCEPT`, `REVISE`, or `BLOCK`.
- `execution-context-scout`: bounded source/context discovery.
- `execution-validation-scout`: focused validation command selection and
  failure diagnosis.

Handoffs should be concise: objective, refs, constraints, expected output, and
validation signal.

Critic output should be ordinary task/session output with a first line of
`ACCEPT`, `REVISE`, or `BLOCK`.
