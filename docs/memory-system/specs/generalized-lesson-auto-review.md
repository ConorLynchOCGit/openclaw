# Generalized Lesson Auto-Review And Promotion

## Purpose

Generalized auto-review proved that broader candidate families can resolve
through bounded clustered machine review instead of creating an indefinite human
queue.

That is now a substrate direction, not a generalized-family-only privilege.

## Current live posture

Live now for the currently landed generalized families:

- workflow lessons
- project rules
- unmet needs

The current generalized path supports:

- `hold_for_more_evidence`
- clustered duplicate handling
- bounded stale rejection
- explicit supersede lineage where appropriate
- approved-only hybrid retrieval after promotion

## What this proved

Auto-review proved that the system can support:

- normalized evidence clusters
- bounded queue behavior
- machine promotion without manual backlog dependence
- explicit lineage

Those are exactly the lifecycle concepts flattening should make available across
the broader family set through shared substrate.

## What flattening will absorb into shared substrate

The flattening phase should take what generalized auto-review proved and turn it
into one shared clustered lifecycle engine with family policy hooks.

Shared substrate should own:

- cluster identity
- subject identity
- approval threshold evaluation
- stale rejection
- supersede lineage plumbing

Family policy should still own:

- cluster key fields
- subject key fields
- contradiction rules
- threshold tuning

## What remains intentionally family-specific

- unmet needs may stay more conservative about automatic supersede
- project rules remain project-scoped guidance
- workflow lessons remain broader repo-operating guidance rather than project
  fact memory

## What future family work must not re-implement locally

Do not create another bespoke:

- hold queue
- promotion evaluator
- stale-cluster cleaner
- supersede lineage tracker

Future families should land on the shared lifecycle engine defined in
`/memory-system/specs/unified-clustered-lifecycle`.

## Next sequencing note

Auto-review is no longer the main missing capability. The next missing
capability is flattening the lifecycle and correction substrate that the
generalized families already partially proved.
