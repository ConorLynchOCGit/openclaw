# Unmet-Need Planning

## Purpose

Unmet-need memory stores repeated missing-support or missing-capability signals
as recommendation-only memory.

## Current live posture

Live now:

- bounded named-project unmet-need capture
- clustered hold and auto-review
- approved-only hybrid retrieval
- recommendation-only application posture

## Intentional product-policy boundaries

Unmet needs remain:

- recommendation-only
- explicitly non-procurement
- explicitly non-install
- explicitly non-approval

They are planning memory, not action-taking memory.

## Updated flattening posture

Unmet needs already share some substrate, but they still depend on the broader
unfinished control-plane work for:

- real application selection
- retrieval/routing control-plane integration
- declarative conservative correction posture
- proof adapterization

## What remains intentionally family-specific

- application mode remains `recommendation_only`
- capability-granular subject identity may remain more conservative than other
  guidance families
