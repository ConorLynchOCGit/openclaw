# Phrase Induction

## Purpose

Phrase induction is a capability for improving deterministic matching using
reviewed phrase patterns derived from already approved memories.

Phrase induction is not:

- broad semantic fallback
- new memory approval
- a reason to make every family share the same phrase behavior

## Capability versus substrate

### Capability

Phrase induction is allowed only where:

- the family has stable canonical targets
- repeated phrasing can safely map to the same approved memory
- a reviewed phrase artifact improves deterministic matching

### Substrate

The flattening phase introduces a unified phrase-pattern engine that manages:

- proposal creation
- review and rejection
- approved pattern storage
- deterministic feed-through to the same family

The substrate is shared even when family eligibility is not.

## Current live posture

Phrase induction is live for:

- approved workflow lessons
- approved response-style memories

Phrase induction is not live for:

- project facts
- recurring procedures
- project rules
- unmet needs

That is an intentional policy split, not merely unfinished work.

## Family eligibility rules

### Good fits now

- workflow lessons
- response style

These are good fits because phrase artifacts can safely point back to stable
guidance targets.

### Poor fits now

- project facts
- recurring procedures
- project rules
- unmet needs

These remain poor fits because:

- facts are truth-sensitive and value-bearing
- procedures are better represented by structure than by phrase alias
- rules and unmet needs may eventually justify phrase support, but the current
  artifact model is not yet clearly safe

## Flattening implications

The flattening phase should unify the implementation substrate while preserving
these policy differences.

Future family work must not:

- build a new phrase subsystem per family
- treat shared phrase infrastructure as permission to enable phrase induction
  everywhere

## Reviewed phrase lifecycle

Phrase induction remains:

- approved-memory anchored
- reviewed
- explicit
- family-local

Approved phrase patterns may only feed deterministic matching to the same
family anchor. They must not become cross-family semantic hints.

## Non-goals

- generic alias learning across all families
- semantic retrieval expansion
- broad subject-alias induction for project facts
